## 개발 목적

AndroidEQModule이 **입력 sample rate와 출력 sample rate를 동일하게 유지하는 same-rate DSP 모듈**로 동작하면서, 권장 지원 범위인 **44,100 Hz ~ 384,000 Hz**에서 20-band Parametric EQ를 안정적으로 처리하도록 고도화한다.

핵심 원칙:

```text
입력 PCM sampleRate == FineTuneEQEngine sampleRate == 출력 PCM sampleRate
입력 frame count == 출력 frame count
resampling 없음
```

> 참고: 사용자 요청의 `44100-38400Hz`는 이전 권장안 문맥상 `44100-384000Hz`로 해석한다. 만약 상한이 실제로 `38400Hz`라면 44.1kHz보다 낮아 범위가 모순되므로 별도 정책 결정이 필요하다.

## 전문가 분석 요약

현재 코드 관찰:

- `FineTuneEQEngine(double sampleRate)`는 sampleRate를 생성자에서 받는다.
- 구현 전 sanitize 정책은 `sampleRate < 8000 || sampleRate > 384000`이면 48000으로 fallback이었다. 구현 결과는 하단 실행 결과 업데이트 기준으로 `44100Hz ~ 384000Hz`이다.
- RBJ 계수는 `w0 = 2πf / sampleRate` 기준으로 계산되므로, 엔진 sampleRate와 실제 PCM sampleRate가 반드시 같아야 주파수 위치가 정확하다.
- `process(inputPCM, outputPCM, numFrames)`는 frame count를 바꾸지 않으므로 same-rate DSP 구조와 잘 맞는다.
- 기본 20-band wrapper 주파수는 최대 20kHz이며, 44.1kHz의 Nyquist 22.05kHz보다 낮아 44.1kHz 이상 범위에서는 기본 preset이 유효하다.
- `frequency >= sampleRate/2`인 band는 현재 flat 처리된다. 44.1kHz~384kHz 범위에서는 고주파 band clamp/flat 정책을 명확히 테스트해야 한다.

전문가 판단:

- 이 모듈은 **sample-rate converter가 아니라 same-rate IIR EQ**로 유지하는 것이 맞다.
- sampleRate 변경은 filter coefficient와 delay state 의미를 바꾸므로, 재생 중 임의 변경보다는 `release/init(newSampleRate)/updateConfig` 또는 명시적 `setSampleRate()` + state reset 정책이 필요하다.
- Android player/decoder 계층이 sampleRate를 결정하고, EQ 모듈은 해당 sampleRate를 받아 같은 frame 수로 처리해야 한다.

## 문서 기반 제약 사항

- DSP 파이프라인 `Preamp → 20-Band Biquad Cascade → Soft Limiter`는 변경하지 않는다.
- 20-band Parametric EQ 범위만 유지한다.
- 입력/출력은 stereo interleaved Float32 PCM을 유지한다.
- sampleRate 고도화는 resampling 추가가 아니라 coefficient 계산 기준과 검증을 강화하는 작업이다.
- 지원 범위는 `44100 <= sampleRate <= 384000`으로 정의한다.

## 잔여 리스크 / 후속 과제

- 실제 Android device/AudioTrack가 352.8k/384k output을 지원하지 않을 수 있음. 이 경우 앱 I/O 계층에서 지원 sampleRate를 협상해야 하며, EQ core는 same-rate DSP만 수행한다.
- 384kHz에서 매우 높은 frequency band를 UI가 제공할지는 제품 정책이다. Core는 Nyquist 기준으로 안전 처리만 보장한다.
- 38,400Hz 지원이 실제 요구라면 본 계획과 별도 amend가 필요하다. 38,400Hz에서는 20kHz 기본 band가 Nyquist를 초과한다.
