## 개발 목적

`README.md`의 제품 설명이 실제 코드 동작과 1:1로 일치하도록 Android Custom 20-Band Parametric EQ Module을 검증·보강한다.

목표 문구는 다음과 같다.

> Android 또는 일반 C++ 환경에서 오디오 스트림에 20-band Parametric EQ를 적용하는 독립형 C++ DSP 코어. RBJ Audio EQ Cookbook 기반 수식을 따르며, 오디오 I/O 계층(Oboe/AAudio/AudioTrack)과 분리된 블랙박스 모듈로 동작한다. 파이프라인은 `Preamp → 20-Band Biquad Cascade → Soft Limiter`이다.

이번 작업은 위 문구를 보수적으로 낮추는 것이 아니라, **실제 구현·빌드·테스트가 그 문구를 만족하도록 만드는 것**이 목적이다.

## 현재 코드 검수 요약

- `Preamp → 20-Band Biquad Cascade → Soft Limiter` 순서는 `FineTuneEQEngine::process()`에서 구현되어 있다.
- `BiquadFilter`는 lock-free coefficient publication과 sample ramp 구조를 갖고 있다.
- `FineTuneEQEngine`은 현재 20개 미만 band를 flat target으로 채우는 방향의 구현을 포함한다.
- `FineTuneEQEngine`은 invalid sampleRate/preamp/frequency/Q/gain에 대한 방어를 일부 포함한다.
- `computeAutoPreampDB()`는 audio-thread active coeff가 아니라 config-side `targetSnapshot`을 읽도록 개선되어 있다.
- `AudioEngineJNI`는 `updateConfig`, `processDirectBuffer`, `computeAutoPreampDB`에 in-flight guard를 적용해 release와의 UAF 위험을 줄였다.
- 현재 기본 입력은 `gains[20]`, `qFactors[20]` 배열을 지원하지만 `gainMin/gainMax/qMin/qMax`를 포함한 명시적 wrapper 구조는 아직 없다.
- 가장 큰 미충족 항목은 host CMake 빌드 실패와 공식 standalone regression harness 부재다.

## 문서 기반 제약 사항

- DSP 파이프라인 순서는 반드시 `Preamp → 20-Band Biquad Cascade → Soft Limiter`로 유지한다.
- EQ는 고정형 Parametric EQ로 유지한다.
- 입력/출력은 stereo interleaved Float32 PCM을 유지한다.
- 20-band invariant를 유지한다. 사용자 config가 0~19개 band만 제공해도 내부 20개 filter 중 나머지는 flat으로 처리한다.
- Android I/O 계층과 DSP 코어 분리를 유지한다.
- 오디오 스레드 경로에 mutex, heap allocation, JNI array copy, blocking wait를 추가하지 않는다.

- [ ] `gainMin/gainMax`는 `gains[i]` clamp 정책으로만 사용

## Phase 4. Parameter sanitize 정책 완성

### 목표

잘못된 UI/JNI/preset 값이 들어와도 NaN, Inf, IIR 폭주, crash 없이 safe fallback으로 동작하게 한다.

### 구현 태스크

- [ ] sampleRate가 finite가 아니거나 8000~384000 범위 밖이면 48000Hz fallback
- [ ] `preampDB` NaN/Inf는 0dB fallback
- [ ] `frequency` NaN/Inf/0 이하/Nyquist 이상은 해당 band flat 처리 또는 정책 clamp 중 하나로 고정
- [ ] `gainDB` NaN/Inf는 해당 band flat 처리 또는 0dB fallback 중 하나로 고정
- [ ] `qFactor`/shelf slope NaN/Inf/0 이하 처리 정책 고정
- [ ] unknown `EqFilterType` 처리 정책 고정: default peaking 또는 flat. 문서와 코드 일치
- [ ] soft limiter 입력이 NaN/Inf일 때 출력 오염 여부 확인. 필요 시 finite guard 추가

### 자체 테스트

- [ ] `sampleRate = NaN`, `sampleRate = -1`, `sampleRate = 1e9` 생성 후 process가 finite 출력
- [ ] `frequency = 0`, `frequency = Inf`, `frequency >= Nyquist` 입력 후 finite 출력
- [ ] `gainDB = NaN/Inf`, `preampDB = NaN/Inf` 입력 후 finite 출력
- [ ] `qFactor = 0`, 음수, NaN 입력 후 finite 출력
